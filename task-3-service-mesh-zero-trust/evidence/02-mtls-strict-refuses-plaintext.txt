======================================================================
 EVIDENCE: mTLS STRICT refuses a plaintext caller
======================================================================

PeerAuthentication in effect:
  payments/default mode=STRICT

The caller runs in namespace 'mesh-outsider', which has NO sidecar
injection. This matters: a meshed pod cannot demonstrate this, because
its own sidecar would transparently upgrade the connection to mTLS and
the request would succeed for the wrong reason.

It targets ledger-api's POD IP directly (10.42.0.248:8080), bypassing
the Service, so the only thing that can refuse it is the destination
sidecar's STRICT listener.

$ curl http://10.42.0.248:8080/health
  curl: (7) Failed to connect to 10.42.0.248 port 8080 after 2 ms: Could not connect to server
http_code=000command terminated with exit code 7

REFUSED at the transport layer. Note there is NO HTTP status code:
the connection never became an HTTP conversation. That is the
signature of an authentication failure, and it is deliberately
different from the 403 in 03-authorization-identity.txt, which is an
AUTHORISATION failure on a connection that did complete a handshake.
